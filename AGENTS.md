# THEIBS interface language

- All user-facing interface text must be in English, including labels, help, errors, status messages, accessibility names, and server messages displayed by the web app.
- Voice recognition may offer PT-BR and EN-US. Portuguese spoken commands and examples are permitted only inside the PT-BR recognition guide or grammar. Keep the surrounding interface and voice state messages in English.
- Preserve poker rules, calculations, API keys, identifiers, and stored data formats when changing copy. Check both voice languages and responsive layouts after UI copy changes.

# Multiway interaction invariants

- Continuous sessions belong to Multiway. Keep simple Analyze, Train and Simulation behavior independent. Prioritize a compact, stable desktop decision surface; performance and history are secondary collapsible views.
- Keep the authoritative actor, selected player, selected historical action, card target and input context separate. Up/Down traverse only confirmed actions in the current street and its real-turn marker, without wrapping or including mandatory blinds. F/G/H act at the real turn or correct the selected historical action using its prior state; H must identify that selected player. Preserve incompatible subsequent history for recovery instead of inventing actions.
- One physical key press produces one command. Native inputs and active editors take precedence over review/results and table capture. Enter confirms an editor, returns from review, shows/prioritizes Hero EV, or closes a hand according to context; it never automatically bets a recommendation.
- Hero and board cards can be entered independently of the actor. Future board cards remain drafts and cannot enter an earlier decision. EV runs only on the real Hero decision with sufficient confirmed inputs; selection alone does not invalidate or recalculate it.
- B corrects button/positions; N edits the selected player's observed stack without creating a poker award. Shift alone and apostrophe restart the current attempt only in capture, retain the interrupted attempt, reuse that hand's opening snapshot and do not rotate the button. Shift combinations, native fields, composition and held-key repeats never restart a hand.
- Normal hand continuation settles and archives once, rotates positions once and posts new blinds once. Unknown results are archived as incomplete; next-hand opening references come from the previous opening stacks and remain visibly estimated. The unresolved pot stays in its original history and is neither refunded nor moved to the next hand.
- Result selection uses 1–9 for Hero-relative opponents A1–A9 and 0 for Hero, with arrows/Tab selecting the pot and Space as an alternative. Numeric shortcuts toggle only eligible winners in the focused pot; monetary fields retain native numbers. Enter confirms once; H does not select Hero. Shown cards are optional. Preserve side-pot eligibility and distinguish awards from returned unmatched bets.
- Performance filters must update curve, counts and hand list together, deduplicate by hand identity and keep incompatible units separate. Count a win for any undivided pot won, a tie only for split pots won, and a loss for no pot won. Keep interrupted/incomplete attempts separate, show unknown-result gaps, and exclude rebuys and stack corrections from poker profit. Saved feedback requires a completed storage operation.
- For scoped interaction deliveries, run syntax checks (`node --check public/multiway-performance.js`, `node --check public/keyboard-controller.js`) and focused browser checks for history selection, H targeting, next-hand idempotency, reload recovery and shared performance filters. Broader suites, long simulations and benchmarks require the matching task scope; the full existing suite is `npm test` from `codigo-fonte`.
